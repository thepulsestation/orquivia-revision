Custom applications · 3 MIN

Do you need an app, or a clearer tracking process?

Imagine a practice with a tracking spreadsheet for each project. It works until preparing a meeting requires comparing versions, searching messages and checking which information is current. The first question is not which app to buy. It is which decision the current system makes difficult.

The spreadsheet is not always the problem

If nobody knows when to update a status or what ‘pending’ means, an app will reproduce that ambiguity. Before development, define what gets recorded, who maintains each piece of information and what allows an item to move to the next status. A shared view with fewer fields may resolve much of the process.

When the need changes

The need changes when the same information feeds several projects, access differs by role, or the next step depends on a date, a document and an approval. If maintaining those relationships requires copying data or repeatedly inspecting a spreadsheet, an application may provide something that simplifying the process alone cannot.

An app with a clear job

A first version could bring together milestones, owners and outstanding documents across a group of commissions. Each field would have an identified source. Alerts would show what prevents progress, while the project view would provide the information needed to respond to a client. Resolve that workflow before adding features nobody needs yet.

The design must also make clear what happens if a connection fails or information is not yet available. Showing the last update and outstanding items distinguishes confirmed information from an incomplete picture. Role-based access and the ability to retrieve the data are part of the design, so the application fits the practice’s operations.

Measure the work needed to keep tracking current

During a pilot, observe the work needed to keep tracking current: where data is entered again, how many copies need correcting and which records become outdated. Also check that each role can access the information it needs. Compare this upkeep with the previous workflow. The app makes sense if it manages relationships between projects and supports a larger portfolio without multiplying its administration.

Start with the last meeting

Gather the spreadsheet used in the last meeting, the questions left unanswered and the sources that had to be consulted. That example makes it possible to analyse the cause and propose a focused solution: refine the process, connect information or build an app. Orquivia defines the recommendation and can develop the selected workflow, with a trial that establishes its usefulness before expansion.
